Commercial brief // buyer and executive context

A proof-first path from software evidence to scoped engagement.

Conxian Labs builds and operates the software surfaces around the Conxian ecosystem. Buyers can start with public source, local evaluation, and documented boundaries, then choose a bounded pilot or a contract-scoped path when the evidence and use case justify it.

Current public posture

Four surfaces, four honest readiness boundaries.

The public portfolio is intentionally evidence-led. Readiness is stated per surface; a repository, demo, or local response is not by itself a hosted-service, settlement, custody, or availability commitment.

Gateway Beta and pilot-first integration surface. Local and self-hosted evaluation are the current entry points.
Wallet Stable, non-custodial, Android-first reference client for demo and integration-to-launch work.
SDK + Core SDK is Beta/conditional; Core is live shared foundation and not a paid fourth tier.

Four public software surfaces

Each surface has a distinct role in evaluation and engagement. Follow the source and readiness evidence before treating a capability as a fit for a specific program.

Beta / pilot-first

Gateway

Conxian Gateway is the integration surface for application workflows and verification rehearsal. The current public path is local or self-hosted pilot work; there is no generally available hosted endpoint or production settlement claim.

Evaluate now: source, developer sandbox, health and supported-chain discovery, and agreed local proof rehearsal.

Stable reference client

Wallet

Conxius Wallet is a stable, non-custodial, Android-first reference client. It supports demo and integration-to-launch evaluation; it is not a hosted or custodial service, and this brief makes no mainnet-proven claim.

Evaluate now: client source, local signing boundaries, device assumptions, and a scoped integration plan.

Beta / conditional

Conxius Enclave SDK

Conxius Enclave SDK is the builder surface for enclave, signing, attestation, and key-management boundaries. It is available for local evaluation and integration work; no production readiness or provider enablement claim is made here.

Evaluate now: repository capability and readiness documents, local builds, and the specific interface needed for the use case.

Live shared foundation

Core

lib-conxian-core is the live shared software and credibility foundation beneath the public stack. It exposes stable API and fail-closed verification boundaries while launch and commercial gates remain in progress.

Commercial boundary: Core is shared foundation software, not a paid fourth tier or a promise that every dependent surface is ready.

What can be evaluated now

Evaluation should produce evidence that a buyer, engineering team, and security reviewer can inspect together.

  • Review the four source repositories and the readiness material linked from them.
  • Build and inspect the Conxius Enclave SDK locally against the documented capability boundary.
  • Run a Wallet reference-client or integration rehearsal on the agreed Android environment without transferring custody.
  • Rehearse the Gateway developer path locally or against an instance explicitly provided for a pilot.
  • Use Core APIs and fail-closed verification boundaries as shared evidence, while recording dependent-surface gaps separately.

What this brief does not claim

Buyer boundary: Public source and a successful local rehearsal do not create a commercial entitlement or readiness certification.
  • No generally available hosted Gateway endpoint or production settlement service is represented.
  • No custody of funds, assets, private keys, or signing control is represented.
  • No blanket provider enablement, adapter coverage, mainnet proof, or production-readiness claim is represented.
  • No uptime, SLA, operational guarantee, support response target, or compliance commitment exists unless written for the engagement.
  • No fixed public price, quota, credit balance, or customer usage ledger is implied by this brief.
