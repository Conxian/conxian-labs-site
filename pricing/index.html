Commercial boundary // packaging guidance

Price the operating path, not the open protocol.

Conxian Labs separates open-source software from optional operational services. The Conclave SDK is MIT-licensed and free for local development. Gateway access starts with local and sandbox rehearsal, then moves to pilot or contract-scoped operations where readiness and payment rails are actually enabled. Conxius Wallet remains non-custodial and follows a demo and integration-to-launch path.

Payment paths and expectations

The native path depends on the product, route, and readiness state. We publish no invented amount here; the relevant commercial boundary is the mechanism and the agreed scope.

Free / local

Open source and local work

The MIT SDK, source inspection, and local development are free. A self-hosted or local rehearsal is not a promise of hosted capacity, quotas, or production support.

Pilot

Gateway pilot terms

Pilot access is arranged around the instance, route family, readiness evidence, and onboarding needed for the engagement. Terms are scoped rather than a public self-serve price.

Metered

Route-level x402 / Lightning

Selected premium proof, execution, or settlement operations may use a route-level x402 challenge and Lightning settlement where enabled and configured. This is conditional and does not make every endpoint paid.

Custom contract

Enterprise contract / invoice

Institutional message and settlement domains, private deployments, admin surfaces, compliance or support terms, and any availability commitment are scoped by contract or invoice.

Optional convenience

Stripe is not the native rail

Stripe may be offered as an optional convenience for approved top-ups or subscriptions when a specific engagement supports it. It is not the core native rail for route-level protocol settlement and is not a general availability claim.

Frequently asked questions

What is free?

The Conclave SDK source is MIT-licensed and local development is free. Local Gateway and Wallet workflows can be run for development or rehearsal, but that does not create a free hosted service, public token, quota, or production support commitment.

Do I need a commercial license for the SDK?

No commercial license is required for the MIT SDK itself. Commercial scope applies to optional managed operations, onboarding, private deployment, or support terms that are separately agreed.

How do Gateway sandbox and pilot engagements work?

The current Gateway path is local/self-hosted and pilot first. The developer sandbox covers health, supported-chain discovery, and local verification or rehearsal against an instance you control or have been given access to. It is not a production settlement demo.

How do x402 and Lightning payments behave?

Where enabled, selected routes can return a route-level x402 payment challenge and use a configured Lightning adapter for settlement. The implementation boundary is conditional: backend configuration, route policy, payment proof, expiry, and replay handling all matter.

Is every endpoint paid?

No. Local development and selected free or public liveness surfaces can remain outside a payment step. Premium proof, execution, or settlement routes may be protected when enabled; the classification is route-level rather than a blanket rule.

Should I expect per-call pricing, credits, invoices, or a hybrid?

That depends on the engagement. Route-level x402 / Lightning can support a per-call boundary where enabled; pilot work can use scoped terms; enterprise work can use an invoice; and a hybrid can be agreed. There is no customer-facing usage ledger, credit balance, quota, or reconciliation system claimed by this page.

Can enterprise customers be invoiced?

Yes, enterprise scope can be priced and invoiced under a written contract. The contract should define the deployment, routes, support, security or compliance scope, and any availability commitment rather than relying on a generic public rate.

Is Stripe the payment rail?

Stripe is only an optional convenience for approved top-ups or subscriptions when a specific engagement supports it. It is not the core native rail for route-level protocol settlement, and current availability is not implied.

What support is included?

Open-source users have the documentation and community path. Pilot onboarding and contact points are scoped. Dedicated support, response targets, SLAs, and compliance assistance are not promised unless they are explicitly written into an enterprise agreement.

Can Conxian Labs white-label the products?

White-label delivery is not a standard promise. It can be discussed as a feasibility and contract question for a specific program, with no delivery, branding, or support commitment until agreed in writing.

How do upgrades work?

Start with local SDK or Wallet work, move to a Gateway or Wallet pilot when an engagement is ready, then expand to metered or enterprise scope only when the route, deployment, and commercial terms are confirmed. An upgrade is not an automatic entitlement to hosted access.

What does onboarding involve?

Onboarding can include repository and documentation review, local setup, route selection, instance access, security boundaries, and readiness evidence. The depth is determined by the product and engagement; there is no one-size-fits-all launch promise.

Does Conxian Labs take custody?

No. The products are designed around a non-custodial boundary: Conxian Labs does not take custody of user funds, assets, private keys, or signing control. Hosted or managed operations, if agreed, do not change that boundary.

Is a hosted Gateway endpoint available today?

No generally available hosted Gateway endpoint is claimed here. Gateway is active development with a local/self-hosted pilot path, and repository documentation treats hosted domains as planned or non-public. Access must be confirmed for the specific pilot or contract.

Is Wallet ready as a hosted service?

Wallet is a non-custodial reference client and product surface following demo and integration-to-launch work. This page does not promise a hosted wallet service, broad white-label delivery, quotas, or production readiness beyond the scope documented for a specific engagement.
